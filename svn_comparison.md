# SVN vs Git

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит (файл из 41 байта в `.git/refs/heads/`). Вся история хранится локально, поэтому создание ветки — мгновенная операция без обращения к серверу.

В SVN ветка — это копия директории на сервере. Чтобы создать ветку, нужно выполнить серверную операцию копирования, что требует сетевого запроса и физического дублирования структуры. Чем больше проект, тем дороже операция.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: единственная копия истории с полными метаданными живёт на сервере. Локально можно только готовить изменения в рабочей копии и смотреть diff, но зафиксировать их в истории (commit) можно только отправив на сервер. Без сети — никак.

В Git, наоборот, коммит создаётся локально, и только push требует сети.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты:** миллионы строк кода и многолетняя история уже в SVN. Миграция дороже, чем поддержка.
- **Крупные бинарные файлы:** SVN умеет блокировать файлы (lock), чтобы два человека не редактировали один бинарник одновременно. В Git это делается сложнее (Git LFS + lock).
- **Жёсткий контроль доступа по папкам:** в SVN права настраиваются на уровне директорий, что удобно в госсекторе и банках.
- **Централизованное управление:** когда политика компании требует единой точки истины и запрещает локальные копии истории.
